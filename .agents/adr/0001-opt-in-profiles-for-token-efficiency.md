# ADR-0001: 行尾来源标注作为可选 Profile 而非默认开启

**日期**: 2026-07-13
**状态**: 已采纳

## 背景

`coding-standard` 需要在代码行尾标注外部依赖的来源、作用和位置（如 `//→ 来源: xxx; 作用: xxx; 位置: xxx`），以提高可追溯性。

## 决策

将行尾来源标注设计为 **可选 Profile**（`profiles/line-annotations.md`），默认关闭。

## 理由

1. **Token 成本**：行尾标注每条约 50-80 字符，对大量代码生成产生显著额外 token 消耗。大多数场景下，标注带来的可追溯性收益不足以抵消每轮消耗。
2. **按需启用**：需要时可通过项目配置（`.coding-standard.yaml`，`annotations: true`）或口头指令开启，不强制所有用户承担成本。
3. **架构一致**：Profile 机制为本仓库的规则模块化提供了统一模式——后续新增的可选能力均可按此方式扩展。

## 后果

- `coding-standard/SKILL.md` 必须维护 Profile 加载规则：激活时检查开关 → 条件 Read 对应文件 → 不激活时跳过
- 自检清单中对标注相关项使用 `【若标注 Profile 已开启】` 条件化
- 用户需知道 `.coding-standard.yaml` 和口头开关两种激活方式
